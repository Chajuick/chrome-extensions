# 내 영상 받기 (yt-grab)

보고 있는 유튜브 영상의 오디오와 영상 파일을 내려받는 확장.
본인이 올린 게임 개발 영상에서 BGM이나 플레이 영상을 빼내려고 만들었다.

확장 아이콘을 누르면 받을 수 있는 형식이 목록으로 나온다. 유튜브 페이지에는 버튼을 심지 않는다.

---

## ⚠️ 현재 대부분의 영상에서 동작하지 않는다

2026년 8월 실제 확인 결과, 유튜브가 **SABR(Server-side Adaptive Bitrate)** 방식으로 넘어갔다.

`Me at the zoo` (jNQXAC9IVRw) 에서 플레이어 응답을 확인한 값:

```
progressiveCount: 0        360p/720p 통합 파일 없음
adaptiveCount:    14
withUrl:          0        URL 을 가진 포맷 0개
withCipher:       0        서명 암호화도 아님
hasServerAbr:     true     serverAbrStreamingUrl 존재
```

포맷 객체의 키 목록에 **`url` 필드 자체가 없다.** 값이 비어 있는 게 아니라 스키마에서 사라졌다.

```
itag, mimeType, bitrate, width, height, initRange, indexRange,
lastModified, contentLength, quality, fps, qualityLabel, ...
```

예전에는 포맷마다 파일 주소를 줬지만, 지금은 `serverAbrStreamingUrl` 엔드포인트 하나만 주고
플레이어가 "몇 초부터 몇 초까지" 를 protobuf 로 인코딩해 POST 로 요청하는 구조다.
**내려받을 파일 주소라는 게 존재하지 않는다.**

이 확장은 "포맷 목록에서 url 을 읽어 `chrome.downloads` 에 넘긴다" 가 전제이므로, 그 전제가 무너졌다.

### 고칠 계획은 없다

고치려면 SABR 프로토콜(protobuf 요청 조립 + UMP 응답 파싱)과 출처 증명 토큰까지 구현해야 한다.
유튜브가 접근을 통제하려고 만든 장치를 우회하는 작업이고, 프로토콜이 바뀔 때마다 깨진다.

**본인이 올린 영상이라면 YouTube Studio → 콘텐츠 → 영상 메뉴(⋮) → 다운로드** 가 공식 기능으로 있다.
이게 정상적인 경로다.

아래 내용은 유튜브가 파일 주소를 주던 시절 기준으로 쓴 것이며, 기록용으로 남겨둔다.

---

## 받을 수 있는 것

| 항목 | 설명 |
| --- | --- |
| 소리만 (원본) | 유튜브가 가진 최고 음질의 오디오 스트림을 **재인코딩 없이** 그대로 저장한다. `.m4a` 또는 `.weba` |
| 소리만 (WAV) | 위 스트림을 디코딩해 16bit PCM WAV 로 저장한다. 편집 프로그램에 바로 넣을 때 쓴다 |
| 영상 + 소리 | 소리가 붙어 있는 파일. **360p, 영상에 따라 720p** 까지만 존재한다 |
| 고화질 (소리 없음) | 1080p 이상. 소리가 없다 |

## 안 되는 것 (설계상 한계)

- **1080p 이상을 소리와 함께 한 파일로 받는 건 안 된다.**
  유튜브는 고화질부터 영상 트랙과 음성 트랙을 따로 내보낸다(DASH). 둘을 합치려면 ffmpeg 같은 도구가 필요한데
  확장 안에는 그런 게 없다. 고화질이 필요하면 "고화질(소리 없음)" 과 "소리만" 을 각각 받아 편집 프로그램에서 합쳐야 한다.
- **mp3 변환은 넣지 않았다.**
  원본이 이미 손실 압축(AAC/Opus)이라 mp3 로 바꾸면 손실 압축을 한 번 더 하는 셈이다. 음질만 떨어지고 얻는 게 없다.
  나눠줄 목적이면 `.m4a` 를 그대로 주면 된다. 요즘 기기에서 다 재생된다.
- **WAV 로 바꿔도 음질이 좋아지지 않는다.**
  손실 압축된 소리를 무손실 컨테이너에 담는 것뿐이다. 파일만 10배쯤 커진다. 형식이 필요할 때만 쓰자.
- **일부 영상은 스트림이 잠겨 있어 목록에 안 나온다.** 그 경우 팝업에 "n개 스트림이 잠겨 있음" 이라고 표시된다.
- **실시간 방송은 받을 수 없다.**

원본 음질이 필요하다면 유튜브를 거치지 말고 작업 파일(WAV/FLAC)을 직접 공유하는 게 항상 낫다.
유튜브는 업로드된 것을 전부 재인코딩하기 때문이다.

## 구조

```
yt-grab/
├─ manifest.json
├─ icons/
└─ src/
   ├─ page.js        # MAIN 월드. 유튜브 플레이어에서 스트림 목록만 읽어온다
   ├─ bridge.js      # ISOLATED 월드. 팝업 ↔ page.js 메시지 중계
   ├─ background.js  # 저장 담당 (chrome.downloads)
   ├─ offscreen.*    # WAV 변환 담당 (서비스 워커엔 오디오 디코더가 없음)
   └─ popup.*        # 형식 목록 화면
```

### 왜 이렇게 나눴나

- 확장의 콘텐츠 스크립트는 격리된 세계에서 돌아서 유튜브 플레이어 객체를 볼 수 없다.
  그래서 `page.js` 만 MAIN 월드에 넣고 `postMessage` 로만 대화한다.
- 유튜브는 화면을 옮겨도 페이지를 새로 읽지 않으므로, 저장된 값 대신 매번 플레이어에게 현재 영상을 물어본다.
- 유튜브 DOM 에 버튼을 심으면 유튜브가 구조를 바꿀 때마다 깨진다. 그래서 UI 를 전부 팝업에 뒀다.

## 확인이 필요한 것

아직 브라우저에서 돌려보지 않았다. 특히 아래 두 가지는 실제로 눌러봐야 안다.

1. **WAV 변환** — 오프스크린 문서에서 만든 blob URL 을 서비스 워커의 `chrome.downloads` 가 받아주는지
2. **원본 저장** — `googlevideo.com` 스트림 URL 을 `chrome.downloads` 가 그대로 받아주는지 (403 이 날 수 있음)

실패하면 팝업에 빨간 오류 메시지가 뜬다. 그 문구를 그대로 알려주면 고칠 수 있다.
