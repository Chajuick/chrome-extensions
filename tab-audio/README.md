# 탭 소리 녹음

지금 보고 있는 탭에서 나오는 소리를 그대로 WAV 로 녹음한다.

유튜브에서 스트림 파일을 받아오는 방식([`yt-grab`](../yt-grab))은 유튜브가 SABR 로 바뀌면서 막혔다.
이 확장은 접근 방식이 다르다. **스피커로 나가는 소리를 받아 적는다.**
그래서 유튜브가 전송 방식을 어떻게 바꾸든 상관이 없다.

## 쓰는 법

확장 아이콘 → `녹음 시작` → 영상 재생 → `정지하고 저장`

녹음 중에는 아이콘에 `REC` 배지가 뜬다. 팝업을 닫아도 녹음은 계속된다.

## 제약

- **실시간이다.** 5분짜리 곡은 5분 걸린다. 빨리 감으면 그만큼 소리가 빠지고, 배속 재생하면 배속된 소리가 녹음된다.
- **소리만 녹음한다.** 영상은 안 된다.
- **탭 전체 소리가 들어간다.** 그 탭에서 나는 알림음이나 광고 소리도 같이 녹음된다. 재생 전에 광고를 넘기고 시작하는 게 좋다.
- **메모리를 쓴다.** 48kHz 스테레오 기준 분당 약 11MB 가 메모리에 쌓인다. 10분이면 110MB 정도. 아주 긴 녹음은 권하지 않는다.
- 녹음 품질은 그 탭이 재생하는 소리 그대로다. 유튜브 영상이면 유튜브가 압축한 음질이 상한이다. 원본보다 좋아지지 않는다.

## 구조

```
tab-audio/
├─ manifest.json
├─ icons/
└─ src/
   ├─ background.js          # 시작/정지 지시, 파일 저장
   ├─ offscreen.html/js      # 실제 녹음. PCM 을 모아 WAV 로 쓴다
   ├─ recorder-worklet.js    # 오디오 워크릿. 소리 조각을 넘겨준다
   └─ popup.*                # 버튼과 경과 시간
```

### 왜 이렇게 나눴나

- 서비스 워커에는 `getUserMedia` 도 `AudioContext` 도 없다. 그래서 녹음은 오프스크린 문서가 한다.
- 서비스 워커는 놀고 있으면 크롬이 꺼버린다. 그래서 녹음 상태를 서비스 워커에 두지 않고,
  오프스크린 문서를 상태의 주인으로 삼는다. 팝업은 열릴 때마다 현재 상태를 물어본다.
- 워크릿이 넘겨주는 건 이미 디코딩이 끝난 PCM 이라, WAV 로 쓸 때 **재인코딩이 한 번도 일어나지 않는다.**
- 탭을 캡처하면 기본적으로 사용자 스피커로 소리가 안 나간다.
  그래서 캡처한 소리를 `destination` 에 다시 연결해 녹음 중에도 계속 들리게 해뒀다.

## 확인이 필요한 것

브라우저에서 아직 돌려보지 않았다. 실패하면 팝업에 빨간 오류 문구가 뜬다.

1. `chrome.tabCapture.getMediaStreamId` 가 팝업 클릭만으로 권한을 얻는지 (activeTab)
2. 녹음 중에도 소리가 정상적으로 들리는지
3. 정지 후 저장 대화상자가 뜨기 전에 오프스크린 문서가 닫혀 blob 이 날아가지 않는지
